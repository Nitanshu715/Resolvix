# V2 Full Audit Report: Diagnosis of the Validation/Leaderboard Gap

## Executive Summary
This audit rigorously investigates the gap between our official leaderboard progression and local validation experiments:
- **Leaderboard V1:** `0.402196`
- **Leaderboard V2:** `0.504000` (+25.3% relative improvement)
- **Local Claimed Validation V2:** `0.9227`

**Key Conclusion:** The local score of 0.9227 was an artifact of an artificially constrained validation setup (true targets + 50k arbitrary distractors). When evaluated on the **realistic full corpus** (searching against all 3,016,817 S2 and 3,170,056 S3 records), the actual V2 baseline was measured at **0.4738 (US) / 0.5079 (India)**, which directly mirrors our real leaderboard baseline of **0.504**!

---

## 1. What Generated the 0.504 Leaderboard Submission?
The V2 submission pipeline implemented:
1. Complete decoupled inverted index blocking for Source 2 and Source 3 (top 25 candidates from each source).
2. NFKD Unicode de-accenting and Indic transliteration.
3. RapidFuzz `token_set_ratio >= 74` threshold matching.
4. Global one-owner post-processing de-collision.

While separating S2 and S3 solved the severe starvation issue of V1 (raising the score from 0.402 to 0.504), the candidate retrieval step was severely bottlenecked by:
- A single token index with aggressive DF truncation and posting slicing (`docs[:150]`).
- Complete omission of house numbers, street numbers, PIN/postal keys, and squished website domain matching.
- **Measured V2 Candidate Recall on Full Corpus:** Only **46.34%** (US) and **61.35%** (India).

---

## 2. Why Did Local Validation Report 0.9227?
In the earlier local experiment:
1. 1,000 S1 entities were selected.
2. Their known true matching S2 and S3 records were explicitly gathered.
3. Only 50,000 arbitrary distractors were added.

Because the true records represented ~1.5% of the total search index, the inverted index easily placed them in the top 25. In the real competition, however, each query must compete against **over 3,000,000 to 5,000,000 distractor records per country**. The true records were being pushed out of the top 25 by common business name tokens.

---

## 3. Measured Root Causes of the Score Loss

From direct error analysis of 1,000 S1 queries against the full corpus:

| Error Category | Percentage of Total Loss | Description / Evidence |
| :--- | :--- | :--- |
| **Retrieval Failure (Missed in Blocking)** | **64.2%** | True target never appeared in candidate set (Pair Recall was only 46.34% on US full corpus). |
| **Website / Domain Masking** | **14.8%** | Target business name formatted as a URL/squished string (e.g., `cdermatology.com`, `williamsscapitalbakerycom`) while S1 has spaces. |
| **Numeric & Street Address Blindness** | **12.4%** | Businesses sharing distinctive address numbers/streets (`4799 Clarence Rd`, `peoria IL 1525`) but having slight name mutations. |
| **Indic Transliteration Variants** | **5.1%** | Variant spellings (`praaivet`, `phaainyaans`, `knstrkshn`) not captured by standard letter matching. |
| **Classifier / Threshold Rejection** | **3.5%** | Candidate retrieved in top-K but rejected by decision threshold. |

---

## 4. Empirical Validation of Multi-Channel Blocking

By replacing the single token inverted index with **Multi-Channel Blocking**:
1. **Compact Domain Channel:** Normalizes squished domains (`certifiedeliterain.com` $\to$ `certifiedeliterain`).
2. **House Number + Street Token Key Channel:** Indexes unique address pairs (`primary_num_street_token`), recovering entities with name mutations.
3. **Salient Name Token Channel with relaxed DF limits.**
4. **Typo-resilient Character 3-Gram Channel.**

### Measured Improvements on Full 6.18M US Corpus (Zero Distractor Subsampling):
- **Candidate Pair Recall:** Jumped from **47.28% $\to$ 86.60%** (+39.32% absolute gain!)
- **Entity-Complete Recall:** Jumped from **26.19% $\to$ 66.91%** (+40.72% absolute gain!)
- **Macro F0.5 on Full Corpus:** Jumped from **0.4738 $\to$ 0.7671** (+0.2933 absolute gain!)

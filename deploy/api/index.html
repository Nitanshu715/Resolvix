System Architecture & Mathematical Foundations

Deep architectural documentation for the Multi-Channel Inverted Indexing, Domain Squish Boosting, and Global One-Owner Consistency De-collision.

1. End-to-End Pipeline Architecture 2. Multi-Channel Inverted Indexing 3. Scoring & Domain Boosting 4. Global One-Owner De-collision 5. Metric Math ($F_{0.5}$)

1 End-to-End Pipeline Architecture

The platform executes a 4-stage pipeline engineered to process millions of records with sub-millisecond retrieval latencies:

  1. Multi-Channel Retrieval: Queries 3 parallel indices (Compact Domain, Street Number, and Salient Name Tokens) to retrieve the top 30 S2 and 30 S3 records.
  2. Pre-formatted Fuzzy Match: Evaluates RapidFuzz token_set_ratio against pre-cleaned phonetic strings.
  3. Domain Match Boost: Overrides similarity to 85 when compact website strings or brand roots match exactly.
  4. Global One-Owner De-collision: When a single S2 or S3 record is claimed by multiple S1 entities, it is strictly assigned to the highest-scoring S1 entity.

2 Multi-Channel Inverted Indexing

Traditional single-key blocking fails in business entity resolution because company names undergo frequent DBA renamings, and addresses suffer from abbreviation drift.

// Channel 1: Compact Domain (Weight: 30.0)
"certifiedeliterain.com" -> "certifiedeliterain"
// Channel 2: Street Number Key (Weight: 15.0)
"1525 Peoria St" -> "1525_peoria"
// Channel 3: Salient Name Tokens (IDF Weight: 2.5 / log(df + 2))
"certified", "elite", "gutters"

3 Scoring & Domain Squish Boosting

Pre-formats all target business names and addresses with phonetic normalization (supporting Hindi and Indic transliterated corporate terms like Pvt, Limited, Prvt, Krnaatk).

When a query's squished brand root matches a target domain key, a high-confidence override elevates the candidate similarity score directly to $\ge 85$.

4 Global One-Owner Consistency De-collision

Under real competition distributions, multiple queries often contest the same branch record. RESOLVIX strictly resolves collisions:

Target_Owner(T) = argmax_{Query} [ Similarity(Query, T) ]

All non-winning claimant entities are pruned, safeguarding global precision and boosting Macro-$F_{0.5}$.

5 The Metric Mathematics: Macro-$F_{0.5}$

Under competition rules, $F_{0.5}$ weights precision over recall:

F_0.5 = (5 * TP) / (5 * TP + 4 * FP + FN)

Notice that False Positives ($FP$) carry a coefficient of 4, while False Negatives carry a coefficient of 1. A single false match harms the score 4x more than an omitted match.

# Business Entity Resolution — Reproduction Guide

## Quick Start

```bash
# 1. Install dependencies (Python 3.10+)
pip install -r requirements.txt

# 2. Train the model (≈ 2–4 hours on a 16-core machine)
python src/train.py

# 3. Generate test predictions
python src/predict.py

# 4. Validate output
cd ../../student_resource
python utils/validate_submission.py \
    --matching output/matching_results.tsv \
    --candidate output/candidate_pairs.tsv \
    --test-dir dataset/test
```

## Pipeline Summary

### 1. Blocking (`blocking.py`)
- Country-partitioned: no cross-country pairs are ever generated.
- Per country: build a TF-IDF inverted index (word tokens, IDF-filtered) over
  S2+S3 business names. Also build an exact-match index over address numeric
  tokens (ZIP/PIN codes ≥4 digits).
- For each S1 entity: query both indices, merge candidates, cap at 50.

### 2. Feature Engineering (`features.py`)
21 float32 features per candidate pair:
- **Name**: word Jaccard, char 3/4-gram Jaccard, fuzz ratio, partial ratio,
  token sort/set ratio, asymmetric token overlaps, length ratio.
- **Address**: word Jaccard, char 3-gram Jaccard, fuzz ratio, partial ratio,
  token sort ratio.
- **Numeric**: ZIP/PIN Jaccard, any-numeric-match flag.
- **Meta**: country match, either-field-empty flags, combined score.

### 3. Model (`train.py`)
LightGBM binary classifier trained on:
- **Positives**: candidates that appear in ground truth.
- **Negatives**: candidates not in ground truth (3:1 neg:pos ratio).
- Early stopping on validation log-loss.
- Threshold grid-searched on validation F_0.5.
